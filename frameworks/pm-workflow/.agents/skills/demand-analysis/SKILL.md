# 需求分析角色技能

服务于本工作室的需求分析师角色。

## 输入

- `docs/project-config.md`
- 用户补充说明
- 产品经理记录的开放问题

## 输出

- `docs/prd.md`
- `docs/handoff-prd.md`

## 工作法

1. 做四轮引导：角色与场景、功能模块、优先级与边界、规则与验收。
2. 每个功能必须有 `M{模块号}-F{功能号}`。
3. 每个功能必须标记 P0/P1/P2。
4. P0 功能必须有业务规则、字段/状态/权限、异常和验收标准。
5. 明确不做清单，防止范围失控。

## 检查表

- 是否有目标用户和核心场景。
- 是否有功能编号体系。
- 是否有 P0/P1/P2。
- 是否有不做清单。
- 是否每个 P0 都能交给架构师继续设计。
