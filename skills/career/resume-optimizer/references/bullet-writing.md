# Bullet 写法

用 bullet 建立信任。强 bullet 要能体现问题、用户行动和结果。

## 标准公式

可灵活使用这个句式：

```text
针对【问题/背景】，作为【角色】，通过【行动/技术/方法】，实现【结果/价值】，并沉淀【可复用产出/复盘】。
```

不是每条 bullet 都必须写满所有字段，但每个项目整体要回答这些问题。

## 四段式项目结构

核心项目优先按“背景 → 目标 → 过程 → 结果”组织：

- 背景：项目所属业务场景、服务对象、原有痛点和为什么值得做。背景必须来自用户真实业务，不要套“企业知识库场景”这类空泛模板。
- 目标：技术目标、成功标准和预期改进方向，例如准确率、延迟、交付效率、覆盖范围或复用能力。
- 过程：用 3-6 条 bullet 展示关键技术方案和工程实现。每条尽量包含“做了什么 → 用了什么方法/技术 → 带来什么效果”。
- 结果：独立总结最终成果，优先放量化指标、上线范围、复用情况、业务影响或可验证产出。

过程 bullet 的写法：

```text
【动作动词】【技术/方法/设计取舍】，用于【解决的问题】，带来【效果/指标/可复用产出】。
```

示例：

```text
设计 BM25 + Dense Retrieval 混合召回链路，通过 RRF 融合排序平衡查全率与查准率，将 Top-10 命中率提升约 20%。
```

## 工作经历 bullet 结构

工作经历强调稳定产出、职责价值和成长曲线，优先使用：

```text
【动作动词】+【工作内容】+【数据】+【对比】
```

对比分两类：

- 横向对比：突出优势、排名、相对表现。适合写满意度、排名、超过同组平均、行业/部门领先。
- 纵向对比：突出成长性、改进幅度、前后变化。适合写周期缩短、转化率提升、成本降低、错误率下降。

横向对比示例：

```text
设计分层激励体系，覆盖 80 名一线运营人员，客户满意度达 98%，部门排名 Top 3。
```

纵向对比示例：

```text
重构供应商管理流程，统一准入、评估和复盘标准，将采购周期从 15 天缩短至 7 天。
```

写作要求：

- 动词开头，不用“负责 XX”单独成句。
- 数据必须服务对比，不要只堆数字。
- 没有横向排名就写纵向变化；没有前后数据就写范围、频次、规模或产出物。
- 不确定的数据可作为建议值标注，最终必须由用户确认。

## 动作动词

优先使用：

- 设计；
- 搭建；
- 实现；
- 优化；
- 重构；
- 封装；
- 接入；
- 推动；
- 协调；
- 分析；
- 定位；
- 标准化；
- 沉淀文档。

只有在后面跟着具体范围和结果时，才使用“负责”。

## 结果类型

可以使用任何真实证据：

- 业务结果：收入、转化率、留存、订单、用户；
- 效率结果：周期缩短、人力减少、自动化率、流程步骤减少；
- 技术结果：延迟、吞吐、错误率、稳定性、测试覆盖率；
- 规模结果：数据量、并发、接口数量、模块数量、团队规模；
- 外部认可：奖项、排名、论文引用、GitHub star、用户反馈；
- 产出物：组件库、报告、看板、API、脚本、文档、Demo。

## 合理包装与量化边界

允许在事实底座上做合理包装，但必须可解释、可追溯、可面试展开。

允许：

- 将真实业务场景提炼成更清晰的项目叙事；
- 将用户实际承担的模块表达为“设计 / 实现 / 主导某模块”；
- 对缺失但合理的指标给出“建议值”，并明确需要用户确认或替换；
- 把团队成果和个人贡献放在同一句里，但必须写清个人负责部分；
- 将技术取舍、复用价值、工程化实践写出来，而不是只列工具名。

禁止：

- 伪造公司、客户、团队规模、上线状态或用户数量；
- 声称使用了实际没有做过的技术；
- 把未来规划写成已完成；
- 把团队整体结果包装成个人独立成果；
- 使用用户面试时讲不清的指标或技术深度。

缺数字时，不要直接编造为事实。可写成：

```text
建议量化：检索命中率提升 15%-30%，端到端延迟 500ms-1500ms，具体数值需用真实日志或评测集确认。
```

## 贡献边界

明确用户是：

- 项目负责人；
- 模块负责人；
- 独立完成；
- 参与某个具体部分；
- 支持其他负责人。

不要把团队结果写成个人成果，除非同时说明用户的具体角色。

## 技术标签与岗位匹配

技术关键词应服务目标岗位，而不是堆栈清单。先确定目标方向，再选择项目亮点：

| 方向 | 优先表达 |
| --- | --- |
| RAG / LLM 应用 | 检索召回、Rerank、Prompt 编排、评估体系、引用溯源 |
| 后端 / 架构 | 接口设计、可插拔架构、异步任务、稳定性、观测性、部署 |
| Agent / MCP | Tool Calling、MCP、工作流编排、权限边界、工具可复用 |
| 数据 / 算法 | 数据处理、特征/Embedding、指标评估、误差分析、实验迭代 |
| 全栈 AI | 端到端交付、前后端协作、产品闭环、成本和延迟优化 |

## 从弱到强

弱：

```text
参与用户管理系统开发，负责前端页面。
```

更好：

```text
针对后台用户审核流程分散的问题，负责用户列表、权限配置和批量审核页面开发；封装通用表格和表单配置，复用到 8 个页面，将单次审核操作从 5 步缩短到 2 步。
```
