# Prompt Engineering Loop

把用户的意图或待优化提示词处理成可执行、可评测、可迭代的标准提示词交付包。

## 核心原则

- 先补上下文，再写提示词
- 先判断任务类型，再选择提示模式
- 分离规则、输入数据、示例、工具、输出格式和失败路径
- 对证据敏感任务显式定义无法回答条件
- 对结构化任务优先使用 schema 或字段清单
- 输出提示词时同步给出评测指标、测试样本设计和迭代方法
- 不把提示词改动当文案润色，而是当模型行为改动管理

## 工作流程

```
用户意图或待优化提示词
    ↓
1. 判断输入形态：意图 / 草稿 prompt / 线上失败样本 / 评测改进需求
    ↓
2. 判断任务类型：抽取 / 证据问答 / 分类 / 生成 / 改写 / 工具调用 / 评审打分 / Agent 工作流 / 其他
    ↓
3. 检查上下文是否足够
    ↓
├── 不足 → 用最少问题引导用户补齐关键上下文
│
└── 足够 → 加载对应参考 → 生成提示词交付包
                         ↓
                 给出评测闭环和验收建议
```

## 上下文补全策略

优先补齐会显著影响提示词成败的信息。不要一次问长问卷；除非用户要求完整表单，否则先问 3 到 6 个关键问题。

必查信息：
1. 任务目标：模型最终要完成什么，可验收结果是什么。
2. 使用场景：给谁用、在哪个系统或流程里用、是否线上自动化。
3. 输入形态：用户输入、检索证据、文件、表格、图片、工具结果或混合上下文。
4. 输出格式：自然语言、Markdown、JSON、函数参数、表格或多段结构。
5. 失败边界：缺证据、字段缺失、工具失败、越权请求、格式不合法时怎么办。
6. 质量标准：准确率、格式合法率、幻觉率、召回率、风格一致性、成本或延迟要求。

如果用户暂时无法补充，基于合理假设生成版本，但必须把假设列入交付文档，并标出需要验证的风险。

## 任务类型判断

| 类型 | 典型信号 | 优先提示策略 |
|---|---|---|
| 抽取 | 字段、票据、简历、病历、工单、表格 | 字段定义 + 缺失返回 null + JSON schema |
| 证据问答 | RAG、知识库、文档问答、依据材料回答 | 证据边界 + cannot_answer + evidence_ids |
| 分类 | 标签、意图识别、情绪、审核 | 标签定义 + 边界例子 + 置信度/原因 |
| 生成 | 文案、方案、文章、邮件 | 受众 + 目标 + 风格 + 长度 + 禁止项 |
| 改写 | 润色、翻译、风格迁移、压缩 | 保留事实 + 改写目标 + 前后对照规则 |
| 工具调用 | Agent、函数调用、自动化流程 | 工具边界 + 调用时机 + 失败处理 + 禁止假装执行 |
| 评审打分 | LLM-as-a-Judge、简历评分、内容审核 | rubric + 先观察后评分 + 输出结构 |
| Agent 工作流 | 多轮任务、长任务、文件操作 | 状态管理 + 检查点 + 工具协议 + 完成条件 |

## 输出策略

默认输出完整交付包，但根据用户请求收缩：

- 用户只要引导语：输出使用说明和信息收集表。
- 用户只要优化提示词：输出任务类型、补充假设、优化后的提示词、关键约束。
- 用户要标准文档：输出完整提示词交付包。
- 用户要评测：输出评测指标、样本集设计、执行步骤、通过标准和迭代方法。
- 用户给失败样本：先分类失败原因，再给定位方法和修复方案。

## 标准交付格式

```markdown
## 使用引导
[告诉用户如何提交意图、现有提示词、输入样本、输出要求和失败样本]

## 需求判断
- 输入形态：
- 任务类型：
- 使用场景：
- 关键风险：

## 已补齐上下文与假设
1. ...

## 完整提示词
[可复制使用的 prompt，清晰分块：角色/目标/输入/规则/输出格式/失败处理/自检]

## 结构说明
- 目标区：
- 输入边界：
- 约束区：
- 示例区：
- 输出区：
- 自检区：

## 评测指标
1. ...

## 评测方法
1. ...

## 可能问题、定位方法与解决方案
| 问题类型 | 现象 | 定位方法 | 优化方向 |
|---|---|---|---|

## 验收建议
[通过标准、回归样本、版本化和回滚建议]
```

## 反模式速查

| 用户说法 | 问题 | 处理方式 |
|---|---|---|
| "帮我优化这个 prompt" | 缺目标和评测标准 | 先问使用场景、输入、输出、失败样本 |
| "让 AI 回答得更好" | 质量标准不可验收 | 转成准确率、完整性、风格、格式等指标 |
| "越详细越好" | 可能堆砌无关规则 | 保留影响行为的规则，移除重复和口号 |
| "不要胡说" | 幻觉边界不具体 | 定义证据来源、cannot_answer 和引用字段 |
| "输出 JSON" | 格式约束不足 | 给 schema、字段含义、缺失规则和合法性自检 |
