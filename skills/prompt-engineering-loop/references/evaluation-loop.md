# 评测闭环

Prompt 改动要用样本和指标验证，不能只凭单次输出观感判断。

## 指标选择

| 任务类型 | 核心指标 | 辅助指标 |
|---|---|---|
| 抽取 | 字段准确率、字段召回率、JSON 合法率 | 缺失字段误填率、证据覆盖率 |
| 证据问答 | 答案正确率、幻觉率、cannot_answer 准确率 | 引用准确率、答案完整性 |
| 分类 | 准确率、宏平均 F1、混淆矩阵 | 低置信样本比例、边界样本表现 |
| 生成/改写 | 需求覆盖率、事实保真度、风格一致性 | 长度合规率、人工偏好胜率 |
| 工具调用 | 工具选择准确率、参数合法率、虚假完成率 | 工具失败恢复率、调用成本 |
| 评审打分 | 与人工分数一致性、排序相关性 | rubric 覆盖率、评分漂移 |
| Agent 工作流 | 任务完成率、回滚率、验证通过率 | 平均轮次、人工介入率、成本 |

## 样本集设计

至少包含：

1. 正常样本：最常见的输入。
2. 边界样本：空值、长文本、多标签、冲突证据。
3. 负样本：证据不足、无关输入、越权请求。
4. 真实失败样本：线上或人工测试中已经失败的案例。
5. 回归样本：历史修复过的问题，防止 prompt 更新后复发。

小规模初测可用 20-50 条样本；上线前评测应覆盖真实分布和高风险边界。

## 评测步骤

1. 固定模型、参数、工具版本和提示词版本。
2. 准备样本输入、期望输出或人工评分标准。
3. 批量运行旧版 prompt 和新版 prompt。
4. 统计核心指标、成本、延迟和格式错误。
5. 对失败样本分类，定位是目标不清、证据不足、格式约束弱、示例缺失、工具边界不清还是模型能力不足。
6. 小步修改 prompt，只改一个主要变量。
7. 重新跑回归样本，确认没有引入新问题。

## 失败分类与定位

| 问题类型 | 典型现象 | 定位方法 | 优化方向 |
|---|---|---|---|
| 任务目标不清 | 输出跑题、重点不稳定 | 看 prompt 是否有可验收目标 | 重写 task 和成功标准 |
| 输入边界混乱 | 把正文当指令或忽略示例 | 检查分隔符和区块标题 | 分离 rules/input/examples |
| 格式不稳定 | JSON 破损、字段缺失 | 统计格式合法率 | 加 schema、字段含义、自检 |
| 幻觉 | 编造事实、无证据结论 | 对照证据和引用 | 加证据边界和 cannot_answer |
| 示例不足 | 边界样本错误率高 | 看失败是否集中在某类边界 | 增加少量高质量 few-shot |
| 工具误用 | 不该调用时调用、漏调用 | 记录工具调用轨迹 | 明确调用时机和失败处理 |
| 规则冲突 | 输出顾此失彼 | 检查规则优先级 | 删除重复规则，排序约束 |
| 模型不匹配 | 小模型无法稳定遵守复杂指令 | 对比模型和 token 成本 | 简化 prompt、加示例或换模型 |

## 验收标准模板

```text
本次 prompt 优化通过标准：
1. 核心任务成功率 >= [目标值]。
2. 输出格式合法率 >= [目标值]。
3. 幻觉率 <= [目标值]。
4. 高风险负样本 100% 按失败规则处理。
5. 平均 token / 延迟不超过 [限制]。
6. 旧版已修复失败样本不回退。
```

## 版本化建议

记录每次 prompt 改动：

- 版本号和日期。
- 修改动机。
- 修改内容。
- 样本集版本。
- 指标变化。
- 已知风险。
- 回滚条件。

## 交付时的评测说明格式

```markdown
## 评测指标
- 主指标：
- 风险指标：
- 成本指标：

## 样本设计
- 正常样本：
- 边界样本：
- 负样本：
- 回归样本：

## 执行方法
1. ...

## 通过标准
1. ...

## 迭代规则
- 如果 [现象]，优先检查 [定位点]，再修改 [prompt 区块]。
```
