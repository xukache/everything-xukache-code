# 首次使用引导

第一次使用这个 skill 时，先让用户知道它不是“一键代写文章”，而是一个公众号文章生产流程。

## 给用户的引导文案

可以直接发送下面这段：

```text
我会用「公众号文章工作流」来辅助你完成这篇文章。

这个 skill 不是直接替你一口气写完，而是按公众号文章生产流程推进：

1. 先理解你的主题和素材
2. 先判断文章目的：教学、复盘、展示效果、引流转化、表达观点，或你指定的其他目的
3. 再判断写作任务、读者状态、文章主承诺和证据
4. 再选择文章外壳：观点文、教程、案例、技术复盘、工具选型清单、Prompt / Skill / MCP 素材包、前端 / AI 编程事故复盘或混合型
5. 给出大纲和待确认决策表，并停下来让你确认方向
6. 只有你明确确认大纲并授权后，才写初稿，同时标出需要你补真实观点、真实 AI 对话、截图和案例的位置
7. 根据你的改写继续做减法、调整结构和保持你的语气
8. 生成 10 组主标题和副标题供你选择
9. 规划封面、顶图、底图、正文配图、项目截图和生成提示词，并在你修改稿件后动态更新配图计划
10. 在正文末尾整理参考链接，并在底图下方生成不超过 5 个内容相关 #tag
11. 如果你要发布到公众号，我可以把最终 Markdown 转成阿栩品牌的公众号 HTML，用于预览和复制富文本
12. 每一步关键产物都会写入 articles/<文章标题>/ 目录，最后保留交接文档

你可以先给我以下任意一种输入：

- 一个文章主题
- 一段粗糙想法
- 一个项目文件夹
- 一批截图或素材
- 一段你和 AI 的对话
- 已经写了一半的草稿

如果你不知道怎么开始，可以直接说：

“我想写一篇关于 XXX 的公众号文章，你先帮我梳理大纲。”

我会先问最少的问题，然后从素材梳理、文章目的、写作任务和读者状态判断开始。
```

如果你有对话记录、代码文件、截图、参考文章链接或零散笔记，我会统一放到当前文章目录的 `raw-materials/` 文件夹里，后续写稿时都从这里调用，避免素材散落在会话和不同目录中。

如果你提供了项目链接、HTML 预览页或本地页面，我会优先判断能不能从项目里截图来支撑正文。对话记录如果已经有文本文件，我会优先提取文字对话，不默认要求你再提供对话截图。

## 首次收集信息

用户第一次使用时，不要一次问太多问题。优先问一个最关键的问题。

如果用户只给了主题，问：

```text
这篇文章的主要目的是什么：教别人做成一件事、分享一次历程和心得、展示效果、引流读者来获取资源/咨询、表达一个判断，还是其他目的？如果你不确定，我可以根据素材先给建议，但大纲前需要你确认。
```

如果用户给了素材文件夹，先读素材，再问：

```text
我先按素材判断文章目的、写作任务、读者状态、主承诺和大纲。你有没有必须保留的观点、截图或归因边界？
```

如果用户给了草稿，先读草稿，再问：

```text
你希望我优先处理哪件事：结构、大纲、口吻、标题，还是配图？
```

## 初始化输出

第一次进入工作流后，先输出：

- 当前识别到的主题
- 已有素材
- 缺失素材
- 原始素材文件夹路径
- 推荐文章目的，以及是否需要用户确认
- 推荐写作任务、读者状态和文章外壳
- 如果适用，推荐对标融合选择：主借智见AI、韦东东、大前端架构师，还是按能力分工
- 推荐下一步

不要一上来直接写完整初稿。生成大纲后必须展示待确认决策表；用户回答检查点问题只代表补充信息，不代表确认进入初稿。只有用户明确说“确认大纲”“开始初稿”“继续写初稿”等授权语句，才写 `draft.md`。生成大纲、初稿、标题候选、配图计划时，都要同步写入文件，并在会话里告诉用户文件路径。用户确认或修改初稿后，要重新检查文章是否按读者认知路径推进，并更新 `visual-plan.md`。

如果用户说“转成公众号格式”“生成公众号 HTML”“排版”“复制富文本”或类似需求，只有最终 Markdown 已确认后才调用 `wechat-axu-styler`。这个步骤只做排版导出，不改正文结构，也不替代配图 skill。
