# 工作流检查点

检查点用于保护用户判断。除非用户明确要求自动完成，否则不要跳过。

## 检查点 1：大纲

产出大纲并写入 `outline.md` 后停下来。不要只在会话里展示大纲。

回复用户时必须展示“待确认决策表”，不要只说文件已写入。表格至少包含：

| 决策项 | 当前建议 | 依据 | 需要用户确认/补充 |
| --- | --- | --- | --- |

表格后再列需要用户确认的问题。必须覆盖：

- 文章目的：教学、复盘、展示效果、引流转化、表达观点，或用户指定的其他目的
- 写作任务：解释、教学/实操指导、说服、共鸣、决策支持或记录复盘
- 技术解释子类型，如果包含解释任务
- 读者当前状态
- 文章主承诺
- 对标融合选择，如果适用：主参考方法、借什么、不借什么、证据门槛
- 开头策略
- 读者认知路径
- 最关键的一节
- 选用的文章外壳
- 章节顺序
- 核心表达
- 哪些素材被删除、合并或只放入素材笔记
- 缺失素材
- `raw-materials/` 中是否已经收齐对话记录、代码文件、链接资料和截图
- 需要哪些截图或对话
- 如果是教学/实操指导：前置条件、预期输出、验证方式和常见错误是否齐全
- 如果是 Prompt / Skill / MCP 素材包：适用场景、可复制内容、替换变量和验证方式是否齐全
- 如果是工具选型清单：筛选标准和固定比较字段是否清楚
- 如果是前端 / AI 编程事故复盘：真实现场、数字、截图、代码或验证证据是否足够
- 归因边界

### 授权规则

- 用户回答检查点问题，只代表补充信息，不代表确认进入下一阶段。
- 用户补充素材、问题或写作偏好，不代表已经确认文章目的。文章目的未确认时，继续停在检查点 1。
- 只有用户明确说“确认大纲”“这个方向可以，开始初稿”“继续写初稿”等授权语句，才进入阶段 4。
- 如果用户补充的信息改变文章目的、写作任务、读者状态、文章主承诺、章节顺序、素材取舍、归因边界或对标边界，必须先更新 `outline.md`，再用简短变更摘要重新展示检查点 1，继续等待确认。
- 不要在检查点 1 的同一轮回复里一边接收补充信息，一边开始写 `draft.md`。

## 检查点 2：初稿方向

完整初稿后停下来。如果文章很长，可以先写开篇和第一节作为代表段落。

请用户检查：

- 初稿结构是否服务已确认的文章目的
- 是否把复盘误写成教程、把教程误写成观点、把展示效果误写成空泛说明，或把引流误写成硬广
- 语气是否太板正
- 开头是否给出继续读的理由
- 文章是否按读者认知路径推进
- 最关键的一节是否获得足够篇幅
- 大纲标记的“最关键的一节”是否真的在初稿中获得最多证据和最清晰结构
- 是否有足够真实过程
- 如果是教学/实操指导：读者是否能照着做出可验证结果
- 如果是清单文或素材包：是否像可用资产，而不是资源搬运
- 如果是前端 / AI 编程事故复盘：是否有真实根因和检查清单
- 是否有段落解释过度
- 是否有应该删除或合并的重复段落
- 用户、AI、skill 的归因是否准确
- 哪些位置需要插入真实对话
- `visual-plan.md` 中用于支撑关键判断的截图或文件证据，是否已在 `draft.md` 对应段落插入占位
- `visual-plan.md` 是否需要根据初稿内容更新
- 是否有项目链接、本地页面或预览地址可以截图补充证据

## 检查点 3：标题

生成标题和副标题候选后停下来。

用户确认或修改标题前，不要基于候选标题重命名文件夹、封面文件或最终 markdown。

## 检查点 4：配图计划

提出图片位置后停下来。

确认：

- 封面图和正文图的区别
- 固定顶图
- 固定底图
- 底图下方 `#tag` 标签候选，不超过 5 个
- Axu/Xukache/公众号视觉资产是否已调用 `axu-article-illustrations`
- 需要用户截图的位置
- 需要生成的图片提示词
- 要插入的已有图片
- 是否存在可截图的项目链接或本地页面
- 对话记录是否已经可以从原始文本提取，是否不再需要对话截图

## 检查点 5：交付

宣布完成前，确认：

- markdown 指向存在的图片，或明确保留占位
- 正文末尾是否有 `参考链接` 区，且只列真实使用过的链接
- 固定底图下方是否有不超过 5 个 `#tag` 标签
- 文章目录符合预期结构
- 最终标题在目录、文件和文章 H1 中一致
- 发布正文中没有误留的本地路径或草稿备注，除非用户明确需要

## 检查点 6：公众号排版导出

当用户需要公众号格式、富文本复制、阿栩品牌排版、HTML 预览或发布前排版文件时，先确认：

- 使用哪个最终 Markdown 文件作为输入。
- 是否直接转换为 `<最终标题>_xukache_wechat.html`。
- 是否需要打开 `wechat-axu-styler` 本地编辑器做视觉微调或复制富文本。
- 是否已经完成正文、参考链接、固定底图和 `#tag`，避免导出后又改 Markdown。
- 是否确认本阶段只做排版导出，不改正文结构、不生成插图、不替代 `axu-article-illustrations`。

导出后确认：

- HTML 文件是否存在。
- 如果打开编辑器，预览是否非空。
- 交接文档是否记录 Markdown 输入、HTML 输出和剩余复制/发布动作。

## 确认话术

检查点问题要简洁。可以给建议，但不能静默替用户决定。

示例：

```text
我建议这篇主任务按“记录复盘 + 解释”走：先写你为什么要改造这个 skill，再写哪些旧规则失效，最后提炼成可迁移的方法。文章外壳用技术复盘。你确认这个方向吗？如果不确认，我可以改成更偏方法论或更偏教程。
```
