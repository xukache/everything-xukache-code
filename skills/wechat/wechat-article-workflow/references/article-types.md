# 写作任务和文章外壳

起草前不要先套文章类型模板。先判断用户为什么要写这篇文章，再判断这篇文章要改变读者的什么状态，最后选择文章外壳。

## 第零判断：文章目的

文章目的先于写作任务。目的回答的是“用户为什么要写这篇”，写作任务回答的是“读者读完发生什么变化”。两者不能混为一谈。

目的不清楚时，不要直接选复盘、教程、案例或观点外壳。可以给建议，但必须让用户确认或明确接受。

| 文章目的 | 典型问题 | 结构倾向 | 必须有的证据或动作 |
| --- | --- | --- | --- |
| 教别人改造 Skill / 做成一件事 | 读者想照着做 | 教学/实操指导 | 前置条件、步骤、文件示例、验证方式、常见坑 |
| 分享改造历程和心得 | 读者想看真实过程和判断 | 记录复盘 + 解释 | 旧问题、触发原因、参考来源、改造动作、认知变化 |
| 展示效果 | 读者想判断这套东西是否有效 | 案例证明 / 效果对比 | 改造前后对比、截图、样例、数据或明确占位 |
| 引流用户获取 Skill / 咨询 | 读者可能需要这套资产 | 转化 / 资产展示 | 痛点、资产能解决什么、适合谁、不适合谁、如何获取 |
| 表达观点或判断 | 读者需要重新看待一件事 | 观点判断 | 核心判断、论据、边界、反例、行动建议 |

同一主题可以服务不同目的。例如“我升级了公众号文章写作 Skill”：

- 教别人改造 Skill：写成教程，重点是步骤、文件和验证。
- 分享改造历程：写成复盘，重点是问题如何暴露、为什么这样改。
- 展示效果：写成案例证明，重点是旧稿和新稿对比。
- 引流用户来要 Skill：写成资产展示，重点是适用人群和获取方式。

如果一篇文章同时想教学、复盘、展示和引流，通常会散。除非用户明确要求混合，默认只保留一个主目的，最多一个辅助目的。

## 第一判断：写作任务

每篇文章只能有一个主任务，可以有一个辅助任务。

| 任务 | 读者当前状态 | 写作重点 |
| --- | --- | --- |
| 解释 | 不懂一个概念、流程或工具 | 用具体场景、类比和步骤让他懂 |
| 教学/实操指导 | 不会做，或做了跑不通 | 给前置条件、步骤、预期输出、验证方式和排错 |
| 说服 | 不信、不想做、觉得没必要 | 从抗拒、误区或代价写起，给证据 |
| 共鸣 | 困惑、焦虑、觉得只有自己遇到 | 先写真实处境，再给判断和做法 |
| 决策支持 | 在几种做法之间犹豫 | 写清取舍、边界、适用和不适用 |
| 记录复盘 | 想知道发生了什么、为什么这样做 | 保留过程、证据、修正和归因 |

如果任务判断不清楚，先看读者读完后应该做什么：

- 要理解：解释
- 要照着做出来：教学/实操指导
- 要开始尝试：说服
- 要觉得被理解：共鸣
- 要做选择：决策支持
- 要看清过程：记录复盘

## 技术解释子类型

当主任务是解释时，再判断技术解释属于哪一种。不要把所有技术文都写成概念科普。

| 子类型 | 适用场景 | 必须写清 |
| --- | --- | --- |
| 概念解释 | 读者第一次接触术语或方法 | 一句话定义、类比、当前案例 |
| 原理拆解 | 读者知道名词，但不理解内部机制 | 模块关系、数据流、为什么这样设计 |
| 代码讲解 | 读者看得见代码，但不知道为什么这样写 | 输入输出、关键变量、执行顺序、设计取舍 |
| 机制对比 | 读者混淆 A 和 B | 差异、边界、适用和不适用 |
| 实现拆解 | 读者想从原理走到代码 | 原理到代码的映射、最小可运行版本、关键测试 |

例如：

- Transformer 架构拆解：主任务通常是解释，子类型是原理拆解。
- 基于纯 Python 实现 Transformer：主任务通常是教学/实操指导，辅助任务是解释，解释子类型是实现拆解。
- Codex 安装和使用教程：主任务通常是教学/实操指导，辅助任务可以是解释或决策支持。

## 教学/实操指导的验收

教学文的目标不是“读者懂了”，而是“读者照着做出来了”。

主任务是教学/实操指导时，大纲必须包含：

- 前置条件：系统、账号、版本、依赖、目录或知识基础。
- 操作步骤：每一步做什么，为什么做这一步。
- 预期输出：读者做对后应该看到什么。
- 验证方式：如何确认已经安装成功、运行成功或实现正确。
- 常见错误：高频报错、卡点和排查路径。
- 下一步扩展：读者跑通后可以继续做什么。

教程不能只列命令。每个关键步骤都要说明它解决什么问题。

## 第二判断：读者状态

大纲前必须写清：

- 读者现在知道什么？
- 读者现在卡在哪里？
- 他为什么会点开这篇？
- 他读完后最可能做什么？
- 哪些内容会让他觉得“这和我有关”？

读者状态决定开头和解释深度。不要写给抽象的“目标受众”。

## 第三判断：主承诺

大纲质量不由章节数量决定，而由每一节是否服务主承诺决定。

```text
读者看完这篇，应该真正拿走什么？
```

每个章节都必须通过四个筛选问题：

- 读者收益：这一节让读者明白什么、学会什么，或少踩什么坑？
- 具体证据：这一节有没有真实过程、文件、截图、对话、选择理由或可复现步骤支撑？
- 通俗解释：如果出现抽象概念或专业名词，是否能用类比、例子或操作场景解释清楚？
- 主线关系：这一节是否直接服务文章主承诺，还是只是因为素材里有所以想塞进去？

不通过筛选的内容不要独立成节。删除、合并到其他章节，或放进素材笔记。

## 读者认知路径

文章结构按读者认知路径组织，不按素材目录、工作流步骤或模板顺序组织。

默认路径：

1. 我为什么要关心？
2. 这和我有什么关系？
3. 具体发生了什么？
4. 关键做法或判断是什么？
5. 我能怎么迁移？
6. 有什么坑或边界？

不是每篇都要完整写完六步。根据写作任务删减。教学/实操指导类文章可以把“具体发生了什么”替换成“具体怎么做”，并增加“如何验证做对了”。

## 开头策略

开头只有一个任务：让读者继续往下读。

可用策略：

- 认知缺口：一个反常识观察，让读者想知道为什么。
- 共鸣场景：一个读者正在经历的具体困扰。
- 结果前置：先给结果，再倒推过程。
- 冲突：两个看似矛盾的事实并列。

写完开头后自检：如果删掉开头，正文几乎不受影响，重写。

## 结构不对称

大纲必须标出最关键的一节。

真实文章不是平均展开。最能支撑主承诺的部分应该获得最多素材、解释和例子。如果每节篇幅看起来都差不多，通常说明主承诺还不够清楚。

## 常见需要删除或压缩的内容

- 功能清单式章节：只列 Skill 有哪些能力，但没有说明为什么这样设计。
- 完整流程复述：把 SOP 每一步都展开，导致读者看不到重点。
- 抽象方法论：只讲“沉淀、闭环、体系”，没有真实操作和例子。
- 参考资料复述：长篇介绍别人文章或工具，而不是说明自己吸收了什么。
- 重复证明：多个段落都在证明同一件事，但没有新证据。

## 文章外壳

文章外壳只在写作任务、读者状态和主承诺确认后选择。

### 观点文

适合表达一个判断或方法。重点不是“我有几个观点”，而是读者为什么应该重新看待这件事。

### 教程

适合读者需要复现结果。只写关键步骤和关键判断，不把每一步操作都当成正文价值。

教程外壳必须服务教学/实操指导任务。缺少前置条件、预期输出、验证方式和常见错误时，不算合格教程。

### Prompt / Skill / MCP 素材包

适合读者需要直接复制指令、配置、提示词、清单或检查项。它属于教学/实操指导的一种，不是资源搬运。

素材包必须写清：

- 适用场景：这组素材解决什么任务。
- 使用边界：适合谁，不适合谁。
- 可复制内容：prompt、Codex 指令、Skill 配置、MCP 使用方式或检查清单。
- 替换变量：读者需要把哪些字段换成自己的项目。
- 验证方式：怎么判断这组素材真的生效。

如果只有提示词或链接，没有使用场景和验证方式，不算合格素材包。

### 工具选型清单

适合读者面对多个工具、组件库、Skill、MCP、资源或方案时需要缩小选择范围。它属于决策支持和工具推荐的混合外壳。

选型清单必须保持固定字段，方便横向比较：

- 适合什么
- 能做什么
- 我怎么看
- 不适合什么
- 入口或替代方案

清单文必须先给筛选标准。没有筛选标准的大清单，只能放进素材笔记，不应作为正文主线。

### 案例

适合解释一个具体项目或一次转变过程。必须写清问题、约束、尝试、关键决策、结果和可迁移原则。

### 技术复盘

适合第一人称记录构建、调试、使用 AI 或创建流程。重点是“我怎么想、怎么做、哪里不对、后来怎么改”。

### 前端 / AI 编程事故复盘

适合记录 Codex、Claude Code、AI 改前端、CSS、性能、review、状态管理、页面实现或工程流程中的真实翻车和修正。

它是技术复盘的子类型，必须有真实现场。默认结构：

1. 现场数字或返工成本
2. 表象：看起来哪里是对的
3. 转折：真正问题不是 X，而是 Y
4. 根因拆解：代码、截图、DevTools、PR / review 或测试证据
5. 修正：怎么改，改完如何验证
6. 检查清单：下次同类任务先查什么

没有真实现场、数字、截图、代码或验证证据时，不要写成事故复盘，可以降级为经验方法文或观点判断文。

### 混合型

只有当单一外壳无法服务主任务时才使用混合型。混合不代表把多个模板拼起来，而是沿同一条读者认知路径调用不同写法。

## 大纲输出要求

选择文章外壳时，简短说明：

- 文章目的，以及是否由用户明确确认
- 主写作任务和辅助任务
- 技术解释子类型，如果主任务或辅助任务包含解释
- 读者当前状态
- 文章主承诺
- 开头策略
- 读者认知路径
- 最关键的一节
- 选用的文章外壳
- 如果是教学/实操指导：前置条件、预期输出、验证方式和常见错误
- 如果是 Prompt / Skill / MCP 素材包：适用场景、可复制内容、替换变量和验证方式
- 如果是工具选型清单：筛选标准和固定比较字段
- 如果是前端 / AI 编程事故复盘：现场证据、真实根因、验证方式和检查清单
- 有意删除、合并或只放入素材笔记的内容
- 哪些章节需要用户补真实对话、截图或结果证据
