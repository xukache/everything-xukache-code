# 多账号融合

只有在每个账号都已单独画像后，才使用本文件。

## 融合原则

按写作能力融合，不按账号身份融合。

示例：

- 用账号 A 的案例重建能力
- 用账号 B 的标题张力
- 用账号 C 的解释清晰度
- 保留用户自己的语言温度

## 融合矩阵

```md
| 能力 | 最佳对标 | 证据 | 借鉴方法 | 对用户的改造方式 | 风险 |
|---|---|---|---|---|---|
| 选题 | | | | | |
| 标题 | | | | | |
| 开头 | | | | | |
| 结构 | | | | | |
| 解释 | | | | | |
| 证据 | | | | | |
| 语言节奏 | | | | | |
| 结尾 | | | | | |
```

## 冲突处理

账号之间写法冲突时，根据用户文章目标选择：

- 教程文：清晰度和验证方式优先于文学节奏
- 案例复盘：具体性和决策证据优先于通用原则
- 观点文：观点强度和反对意见处理优先于步骤完整
- 个人 IP 文：真实感和自我披露边界优先于借来的巧妙表达
- 推荐文：信任和限制披露优先于转化压力

## 融合输出

输出：

- 用户账号默认规则
- 不同文章类型的覆盖规则
- 用户指定时可启用的单对标账号模式
- 禁止借鉴项
- 证据缺口

## 风险信号

出现以下情况要停下来标注风险：

- 融合结果像通用“好文章清单”
- 用户要求融合，但某个账号压倒性支配输出
- 反复出现样本原文的精确表达
- 用户人设被对标账号口吻覆盖
- 没有任何规则提到文章类型

## 规则示例

```md
用于案例复盘文：
- 借账号 A 的“结果 -> 过程 -> 决策点 -> 反思”顺序。
- 借账号 B 在标题里命名具体对象的习惯。
- 不借账号 B 过强的标题压迫感。
- 保留用户第一人称解释，并尽可能加入截图 / 过程证据。
```
