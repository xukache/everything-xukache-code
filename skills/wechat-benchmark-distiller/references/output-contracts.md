# 输出契约和检查

使用能满足用户请求的最小输出契约。

```md

| 账号 | 文章 | 主类型 | 辅类型 | 读者状态 | 文章承诺 | 置信度 | 备注 |
|---|---|---|---|---|---|---|---|

## 观察
- ...

## 缺口
- ...
```

## 契约 E：Skill 资产

当根据蒸馏结果编写新 Skill 时：

- `SKILL.md` 保持精简：触发条件、硬规则、路由、SOP
- 详细分类法和模板放在一层 `references/`
- 包含输出契约
- 包含纠偏机制
- 除非用户明确要求，不要添加 README / changelog

## 契约 F：蒸馏任务目录

当用户提供原始对标素材或需要保存分析结果时，按 `references/output-structure.md` 建立任务目录。至少包含：

```text
benchmark-distillations/<本次蒸馏主题>/
  raw-materials/
  analysis/
    sample-map.md
    article-type-classification.md
  synthesis/
  deliverables/
```

多账号任务必须在 `sample-map.md` 中记录 `account_id` 和 `sample_id`。

目录骨架必须在接收或归档原始素材前创建，不要等蒸馏完成后再补。

## 交付前检查清单

- 风格判断之前是否已有文章类型分类？
- 是否在处理素材前创建了任务目录骨架和空索引文件？
- 多个账号是否已先分别蒸馏，再融合？
- 原始素材是否放在 `raw-materials/`，而不是 Skill 目录？
- 多账号任务是否有稳定的 `account_id` 和 `sample_id`？
- 证据缺口是否明确？
- 借鉴的是方法，而不是人格或原句？
- 是否保留用户风格和约束？
- 输出是否能用于下一篇文章，而不是只能作为分析欣赏？
- 样本薄弱时，结论是否标为暂定？
