# 用户风格整合和纠偏

对标账号是素材。用户自己的账号才是产品。

## 整合层级

### Layer 0：用户不可违背项

文章必须遵守：

- 用户真实经历和证据
- 用户作者人设
- 用户明确不喜欢的表达
- 事实和归因边界

### Layer 1：默认声音

保留：

- 用户偏好的直接程度
- 技术深度
- 个人披露程度
- 幽默感或克制感
- 对 AI / 工具归因的态度

如果未知，标注未知，不要编造。

### Layer 2：借来的方法

把对标方法改造成操作：

- 开头动作
- 章节顺序
- 解释动作
- 证据位置
- 标题承诺
- 结尾动作

### Layer 3：类型覆盖规则

规则可以按文章类型变化。例如：

- 教程文需要更明确的前置条件和验证方式
- 案例复盘需要更多过程证据和决策点
- 观点文需要更强的反对意见处理

### Layer 4：纠偏记录

当用户反馈“这不对”时记录：

```md
## 纠偏
- 日期：
- 触发场景：
- 错误输出：
- 用户反馈：
- 修正后规则：
- 适用范围：当前文章 / 类型规则 / 账号画像 / 长期用户风格
```

不要把每条纠偏都自动升级为长期规则。先标为候选，只有必要时再询问用户。

## 常见反馈映射

| 用户反馈 | 可能问题 | 修正方式 |
|---|---|---|
| 太像对标号 | 复制了声音或人格 | 保留方法，用用户口吻重写 |
| 太 AI | 抽象判断多，证据弱 | 加具体过程，删泛泛夸赞 |
| 结构对，语言不对 | 方法借得太深 | 保留章节计划，重写句子节奏 |
| 标题可以，正文弱 | 标题承诺没有兑现 | 补上匹配标题的证据路径 |
| 不像我 | 用户 Layer 0 缺失 | 询问或从用户旧文章推断 |
| 这个账号不是这么写的 | 类型混淆或样本太薄 | 回到分类和证据 |

## 借鉴规则

借动作，不借句子。

示例：

- “用一个具体失败尝试开头”可以借
- 作者自己的失败经历不能借
- “把尖锐判断放在例子之后”可以借
- 精确比喻通常不要借

## 整合检查清单

交付前检查：

- 每条借鉴规则是否说明来源？
- 每条规则是否说明何时使用？
- 是否区分了文章类型？
- 弱证据是否明确标注？
- 输出是否仍然可能属于用户自己？
