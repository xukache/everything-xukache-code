# JD 拆解

改写简历前，先把每个 JD 翻译成筛选标准。

## 四层 JD 拆解

| 层级 | 要回答的问题 | 简历中的信号 |
|---|---|---|
| 业务目标 | 公司为什么要招这个人？ | 项目背景、业务结果、行业理解 |
| 硬技能 | 必须会哪些工具、语言、方法或框架？ | 技能区、技术动作、产出物 |
| 软能力 | 隐含哪些协作、owner 意识、学习或抗压要求？ | 跨团队协作、模糊问题推进、复盘 |
| 隐性门槛 | 可能有哪些未明说的筛选条件？ | 学历、年限、规模、英文、作品集、行业背景 |

## 招聘诉求判断

将岗位归类：

- 扩充团队：强调快速上手、相关经验和稳定交付；
- 补齐能力：强调某项技能或领域的精准匹配；
- 培养梯队：强调成长性、学习速度、综合潜力和自省。

## 匹配矩阵规则

对每个重要 JD 要求，映射：

- 用户证据；
- 匹配程度：高、中、低、缺失；
- 简历呈现策略；
- 面试风险。

不要堆关键词。关键词必须自然出现在技能和经历证据中。

## 多 JD 处理

当用户提供多个 JD：

- 聚类相似岗位；
- 找出共同核心要求；
- 找出公司特定差异；
- 判断一版简历是否足够，还是需要多版本。
