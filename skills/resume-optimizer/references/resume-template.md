# Markdown 驱动的简历 HTML 模板

当用户需要生成完整格式化简历时，使用本参考文件。目标是让用户和 AI 只维护 Markdown 内容，HTML 只负责加载和渲染模板。

## 文件职责

- `templates/resume-preview/`：完整简历模板包，新增模板页时优先按这个目录结构复制。
- `templates/resume-preview/resume-content.md`：用户填写和 AI 改写的唯一内容源。
- `templates/resume-preview/index.html`：简历预览页面，加载 Markdown 并实时渲染。
- `templates/resume-preview/render-resume.mjs`：无依赖 Markdown 解析和 DOM 渲染逻辑。
- `templates/resume-preview/styles.css`：简历版式和编辑预览样式。

## 用户填写内容

`templates/resume-preview/resume-content.md` 必须覆盖这些区块：

1. 基本信息：姓名、标题、意向城市、当前状态、工作年限、邮箱、电话、头像文字。
2. 简介：按“角色定位 + 差异化优势 + 求职目标”组织；如果是单一明确岗位，求职目标可省略。
3. 技术栈：3 个能力组，每组一个标题和一段能力关键词。
4. 核心项目：每个项目包含标题、技术栈、背景、目标、过程和结果，正文按“四段式：背景、目标、过程、结果”组织。
5. 工作经历：每段经历包含时间、公司、岗位、职责摘要和 bullet；bullet 优先按“动词 + 工作内容 + 数据 + 对比”写。
6. 补充：作品、证明材料、链接或其他可核验材料。

## 改写流程

1. 先完成材料接收、JD 拆解、证据挖掘和简历策略。
2. 在检查点 1 得到用户确认后，才生成或覆盖 `templates/resume-preview/resume-content.md`。
3. 将最强岗位匹配证据放入简介、技术栈和前 1-2 个核心项目。
4. 使用真实可证明的数据；缺数据时保留待确认占位，不编造。
5. 生成核心项目时先确定“用户画像”：目标岗位、真实业务背景、技术侧重、特殊要求。
6. 生成后提示用户用本地服务打开模板：

```bash
cd skills/resume-optimizer
python3 -m http.server 8080
```

然后访问：

```text
http://localhost:8080/templates/resume-preview/index.html
```

如果用户直接双击打开 HTML，浏览器可能阻止加载本地 Markdown。页面会回退到内置 Mock 内容，但正式预览建议使用本地服务。

页面右上角提供“导出 PDF”按钮，点击后调用浏览器打印面板。导出时选择“另存为 PDF”；打印样式会隐藏左侧 Markdown 编辑器和工具栏，只保留右侧简历内容。

## 项目经历生成逻辑

当用户要求从项目、代码仓库或作品集生成项目经历时，先补齐这些输入：

1. 目标岗位：例如 RAG 工程师、后端工程师、LLM 应用开发、Agent 工程师、全栈 AI。
2. 业务背景：团队做什么、服务对象是谁、原有流程或工具有什么痛点、为什么需要这个项目。
3. 技术侧重：检索、Rerank、MCP、可插拔架构、评估、观测性、工程化、前后端交付等。
4. 特殊要求：中英文版本、篇幅、偏业务或偏技术、是否需要量化建议、哪些信息不能写。

核心项目必须使用四段式：

```markdown
### 项目名称 | 时间段 | 角色
- 技术栈：按目标岗位权重排列
- 背景：2-3 句真实业务场景、服务对象、痛点和需求
- 目标：1-2 句技术目标、核心能力和成功标准
- 过程：动词开头 + 技术细节 + 取舍/效果
- 过程：可继续罗列 3-6 条
- 结果：2-3 句汇总核心指标、上线范围、复用价值或产出物
```

格式约束：

- 背景必须具体，避免“企业知识库场景”“业务效率低”等模板话。
- 过程允许多条列表，优先 3-6 条；每条不超过 80 字更适合简历阅读。
- 结果段至少包含一个可验证结果；如需建议指标，必须标注“建议值，需用户确认”。
- 技术栈不按工具出现顺序排列，而按目标岗位相关性排列。
- 如果某个项目无法支撑四段式，先补问事实，不要硬写完整项目。

如果项目来自具体代码仓库，可参考 `references/examples/modular-rag-mcp-project.md` 的亮点拆解方式：先提炼技术亮点、话术方向和可量化角度，再按目标岗位筛选 3-5 个最相关亮点写入过程段。

## 个人简介写法

简介不是自我评价，而是招聘方进入简历后的第一条定位信息。优先使用三段式：

```markdown
## 简介
- 角色定位：年限 + 岗位方向 + 专注领域 + 代表性经历。
- 差异化优势：最能区分候选人的长板，必须尽量用数据、范围、产出物或业务影响支撑。
- 求职目标：应聘岗位 + 希望把哪类经验应用到目标公司的哪类问题上。单一明确岗位或内部流转简历可省略。
```

写法要求：

- 角色定位要具体到岗位和场景，不写“学习能力强”“认真负责”。
- 差异化优势优先写一条最强长板，不要罗列多个泛泛优点。
- 求职目标必须和目标岗位强相关，不写空泛愿景。
- 如果没有目标公司信息，可以写目标岗位和业务方向，不要硬写“贵司”。

示例：

```markdown
- 角色定位：5 年跨境电商产品经理，专注 B 端 SaaS 工具设计，主导 3 款千万级 GMV 产品迭代。
- 差异化优势：擅长通过用户行为分析优化转化路径，曾通过漏斗优化将注册率提升 40%。
- 求职目标：应聘产品经理岗位，希望将用户洞察经验应用于金融科技产品的体验优化。
```

## 脱敏规则

- 不要把用户真实简历信息硬编码到 `templates/resume-preview/index.html`。
- 不要提交真实照片、身份证件、手机号、邮箱、公司内部项目截图或未脱敏客户信息。
- 如需头像，默认使用 `头像文字` 字段生成占位头像。
- Mock 数据必须看起来像真实简历，但不能对应真实个人。

## 审查点

- Markdown 字段是否能完整渲染到页面。
- 页面是否仍出现 Mock 姓名、Mock 邮箱或示例公司。
- 项目是否按“背景、目标、过程、结果”四段式呈现，过程是否包含动作、方法和关键取舍。
- 黄金广告位是否服务目标岗位。
- 用户是否能不改 HTML 只改 Markdown。
