# 经历证据挖掘

将原始经历转成可复用的证据库。

## 从时间线到逻辑线

不要照搬时间流水账。将经历转成有逻辑的故事：

1. 当时有什么问题或机会？
2. 任务或目标是什么？
3. 用户本人具体做了什么？
4. 产生了什么结果、产出物或学习？

这与 STAR 和 PAR 的本质一致。

## STAR/PAR 字段

- Situation/problem：背景和重要性；
- Task/goal：目标或成功标准；
- Action：用户的具体行动，优先使用动作动词；
- Result：量化结果、产出物、外部认可或可观察影响；
- Reflection：学到了什么，如果重做会如何改进。

## 证据质量

强证据具备：

- 与目标 JD 高相关；
- 个人贡献清晰；
- 有难度或复杂度；
- 有数据、产出物、排名、用户反馈或外部认可；
- 能支撑面试追问。

弱证据通常表现为：

- 只描述职责；
- 只写“参与”，不写贡献；
- 把团队结果写成个人结果；
- 没有结果、产出物或复盘；
- 经不起面试追问。

## 经历筛选

优先选择：

- 强相关经历，而不是名头大但弱相关的经历；
- 能讲清细节的经历，而不是包装很大但说不清的经历；
- 有结果证据的经历，而不是只有职责描述的经历；
- 近期经历，除非早期经历特别强。
