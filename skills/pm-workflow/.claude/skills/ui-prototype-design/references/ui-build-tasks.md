# UI 构建任务参考

UI 构建任务用于把设计简报、信息架构和 tokens 转成可逐项实现、逐项验证的原型任务。

## 拆分原则

- 任务按垂直切片拆，不按 HTML/CSS/JS 分层拆。
- 每个任务都要能独立打开、独立看见结果、独立截图验证。
- 基础任务优先：tokens、应用外壳、导航、复用布局、核心组件。
- 高频路径优先：先做用户 80% 时间所在页面，再做低频辅助页。
- 风险优先：最不确定的交互、状态、响应式和数据密度要提前验证。

## 每个任务必须包含

- 任务编号和名称。
- 覆盖页面、功能编号和用户目标。
- 创建/修改的原型文件。
- 复用或新增的布局/组件/tokens。
- 需要覆盖的状态：默认、悬停、聚焦、加载、空、错误、成功、权限异常。
- 验证方式：打开路径、操作步骤、截图视口、预期结果。

## 禁止

- “搭建整体页面”“完善样式”“补齐交互”等不可验证任务。
- 只写“写相关状态”“处理响应式”等空泛描述。
- 未完成当前任务验证就进入下一任务。
