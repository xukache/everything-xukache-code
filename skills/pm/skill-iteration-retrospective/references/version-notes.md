# 版本说明记录

## 2026-05-09：补强职责边界与正式交付格式诊断

```text
Skill：
- skill-iteration-retrospective

迭代目标：
- 让复盘流程能识别目标 Skill 的职责边界漂移、停止条件缺失和正式交付格式缺失。

本次处理的失败样本：
- pm-workflow 在 AI 训练师标注平台需求梳理样本中，完成原型、PRD、流程图和开发交接后，继续建议技术方案、ERD、API 契约和排期计划。
- 用户随后要求把 PRD、流程图、需求笔记、开发交接等关键文档输出成 Markdown，便于版本迭代管理，并提醒技能目的应收敛在业务真实需求和开发可用文档，不要扩大职责边界。

已做修改：
- 触发与门槛：增加对“职责边界漂移”“停止条件”“正式交付格式”的判断。
- 失败归因：新增“职责边界漂移”归因类型。
- 输出规格：增加“停止条件与职责边界”。
- 试跑检查：增加主线完成后是否停在确认/归档/交接，以及是否保留可版本管理源文件。
- 模板：在迭代卡、失败样本、版本说明模板中加入边界、停止点、禁用产物和版本管理格式字段。
- 失败模式库：新增职责边界漂移、只有演示物缺少可版本管理源文件两类模式。

修改原因：
- 旧版复盘流程能识别输入、判断规则和输出接口问题，但对“工作流完成后继续外扩”不够敏感。
- 文档型和产品型 Skill 常见失败不是内容完全错误，而是缺少正式源文件、缺少收敛动作，导致后续版本管理和开发交接返工。

修改后的预期行为：
- 当用户给出一段多轮对话记录时，先抽取目标 Skill 的声明用途、不做事项、完成线和实际下一步建议。
- 如果目标 Skill 把可选下游事项当作默认交付，归因为职责边界漂移，并要求新版规格写清停止条件。
- 如果交付物只有 HTML、截图或演示页，检查是否需要 Markdown、Mermaid 源码、README 索引或其他可 diff 文档。

已知取舍：
- 不把所有下游扩展都判定为错误；只有当目标 Skill 主线已完成、用户未明确要求进入下游专业阶段，或用户要求收敛时，才判定为边界漂移。
- 本轮不重写 pm-workflow，只优化 skill-iteration-retrospective 如何复盘类似问题。

验证计划：
- 旧失败样本回放：用 2026-05-09 的 pm-workflow 记录检查能否识别“技术方案/排期建议越界”和“缺少 Markdown 源文件”。
- 新样本试跑：用一个只要求复盘 UI 输出质量的样本，检查不会过度套用职责边界规则。
- 输出交接检查：确认新版规格会输出停止条件、禁用产物和版本管理格式检查。
```
