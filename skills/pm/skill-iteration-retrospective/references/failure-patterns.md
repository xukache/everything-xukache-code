# 失败模式库

记录可复用的 Skill 失效模式。每条都要能反向指导下一次迭代，不记录一次性情绪或纯文案偏好。

## 职责边界漂移：把下一阶段建议当成默认交付

```text
出现位置：
- 多阶段工作流 Skill 的“接下来要做什么”“继续”“评审通过后”节点。

表现症状：
- Skill 已经完成主线交付，但继续建议或生成技术方案、架构设计、排期承诺等下游专业产物。
- 用户后来提醒要“收敛”“不要扩大职责边界”“回到真实需求/正式文档”。

根本原因：
- Skill 缺少明确完成线。
- Skill 没把“可选下一步建议”和“本轮默认交付”分开。
- Skill 没有把本轮职责边界写进最终交付检查。

预防规则：
- 在失败样本整理阶段抽取目标 Skill 的声明用途、禁用场景和完成线。
- 在新版规格中写明停止条件、禁用或后置产物，以及评审通过后的收敛动作。
- 旧样本回放时专门检查：当用户问“接下来”或“继续”时，Skill 是否先判断主线是否已完成。

正确停止动作：
- 说明主线已完成。
- 请求用户确认评审结果或补齐正式交付格式。
- 只把下游技术方案、架构、排期列为可选后续，而不是默认产出。

示例：
- `pm-workflow` 在产品交付物完成后，曾建议继续产出 `tech-plan.html`、ERD、API 契约和排期。用户随后要求输出 PRD、流程图、需求笔记、开发交接等 Markdown 文档，并提醒技能目的是梳理业务真实需求、产出开发可用文档，不要扩大职责边界。
```

## 输出接口不匹配：只有演示物，缺少可版本管理源文件

```text
出现位置：
- 原型、流程图、PRD、交付说明等文档型 Skill 的最终交付节点。

表现症状：
- HTML 或可视化页面可以演示，但不方便后续 diff、评审批注和版本迭代。
- 用户补充要求输出 Markdown、Mermaid 源码、README 索引或最终交付说明。

根本原因：
- Skill 只定义了演示入口，没有定义正式文档源文件。
- Skill 没区分“用于评审展示的 HTML”和“用于版本管理的 Markdown/源码”。

预防规则：
- 在迭代卡的输出接口中记录正式交付格式和演示交付格式。
- 在新版规格中明确哪些产物需要 Markdown、Mermaid 或其他可 diff 源文件。
- 交付前检查正式源文件是否存在，并确认索引页能指向它们。

正确停止动作：
- 先补齐正式文档源文件和索引。
- 再把 HTML 标注为演示/查看入口。
- 不继续扩展到非本 Skill 职责的技术实现方案。

示例：
- `pm-workflow` 的 HTML 原型、PRD 页、流程页已经可演示，但用户后来要求 PRD、流程图、需求笔记、开发交接都输出为 Markdown，便于版本迭代管理。
```
