# 方案架构 Worker 标准

在 `pm-workflow` 阶段 2 和阶段 2.5 使用本文档。目标是把已确认需求清单转成可设计、可演示、可开发理解的产品结构。

方案架构 worker 合并处理范围、角色、流程、对象状态、信息架构、菜单、页面职责、动作位置和原型覆盖矩阵。它是需求发现和原型设计之间的闸门，防止从功能列表直接跳到页面绘制。

## 主 PM 与方案架构 Worker 分工

- 主 PM：负责确认需求清单已通过、派发方案架构 worker、审核范围是否过大、确认输出是否能支撑原型设计，并把关键取舍拿给用户确认。
- 方案架构 worker：负责把需求清单拆成 MVP 范围、角色权限、业务对象、状态流、主流程、菜单结构、页面职责、动作位置和原型交互覆盖矩阵。
- 主 PM 不得把 worker 输出原样交付；必须检查是否把假设写成事实、是否把后置项放进一期、是否遗漏 must-have。

## 子 Agent 调度规则

每个产品迭代第一次进入方案架构阶段时，主 PM 必须新开真实方案架构 worker。阶段内补充、调整、返工时复用已启动的方案架构 worker，不再重复新开。

任务说明必须包含：

- 已确认的 `requirements-list.md`。
- 用户确认的问题定义、需求清单和范围约束。
- 本阶段允许读取的 reference 和 helper skills。
- 本阶段必须输出的结构。
- 不允许进入设计主题、HTML 原型、正式 PRD、技术架构或排期。

只有在当前工具环境不支持新开 worker，或用户明确要求不要新开时，才允许降级为同一模型内的角色化流程，并在 `notes/stage-workers.md` 记录：

- 未派发真实 worker 的原因：工具不支持 / 用户明确禁止 / 其他。
- 如果是阶段内调整，记录复用了哪个已启动 worker。
- 采用的角色化 worker 流程。
- 读取的 reference 和 helper skills。
- 主 PM 验收结论。

## 阶段引用白名单

方案架构 worker 只能读取以下输入：

- `references/solution-architecture-worker-standards.md`。
- `references/interaction-architecture.md`。
- `requirements-list.md`。
- `notes/requirements.md` 中已确认事实、范围边界、角色、状态、规则和后续澄清问题。
- 全局 `user-story-splitting` skill。
- 全局 `epic-breakdown-advisor` skill。
- 全局 `user-story-mapping` skill。
- 全局 `user-story` skill。
- 用户对需求清单和范围的确认材料。

不得读取或套用以下阶段文档：

- 设计主题、HTML 原型、PRD 浮标和视觉打磨相关 reference。
- 生产级 PRD、流程图 viewer、开发交接和 artifact 交付相关 reference。
- 未经用户确认的外部产品能力。

## Helper Skill 使用规则

| Helper skill | 何时使用 | 作用 | 是否必用 |
| --- | --- | --- | --- |
| `user-story-splitting` | 需求过大、一个迭代吃不下 | 拆成更小、更安全的交付切片 | 大需求时用 |
| `epic-breakdown-advisor` | 后台系统、长流程、多角色协作、依赖多 | 拆主干、依赖、MVP 切片和后置项 | 复杂需求必用 |
| `user-story-mapping` | 需要梳理端到端流程、活动主干、版本切片 | 把角色活动和任务步骤组织成可演示路径 | 工作流型需求必用 |
| `user-story` | 需要把 must-have 改成可验收表达 | 明确角色、动作、结果和验收信号 | 关键需求进入范围时用 |

调用前必须先将 bundled 副本同步到全局 skills 目录，再按正常 skill 名称调用。worker 必须记录“已用 / 未用 / 未用原因”。

## 主 PM 验收门槛

主 PM 必须逐项检查：

- 没有“本次不做”，不通过。
- 每个 must-have 没有进入一期原因，不通过。
- 把“先验证 / 后置 / 不做”的需求偷偷放进 must-have，不通过。
- 没有业务对象、状态、角色边界或主流程，不进入原型设计。
- 任何 must-have 没有进入原型交互覆盖矩阵，不进入原型设计。
- 页面只是功能堆叠，没有主要用户和主操作，不通过。
- 菜单命名不符合用户业务语言且未提示用户确认，不通过。
- 未说明单页或多页原型选择理由，不进入原型设计。

## 用户确认输出

主 PM 给用户的方案架构确认输出必须包含：

- MVP 范围表。
- 角色和默认入口。
- 主流程和异常流程。
- 菜单与页面职责。
- 关键动作位置。
- 原型交互覆盖矩阵。
- 多页面拆分建议。
- 下一步：确认后才进入设计主题和原型设计。
