# 需求分析角色技能

服务于本工作室的需求分析师角色。

## 输入

- `docs/project-config.md`
- `docs/workflow-state.json`
- 用户补充说明
- 产品经理记录的开放问题

## 输出

- `docs/prd.md`
- `docs/handoff-prd.md`

## 工作法

1. 开始前输出阶段开场卡：当前用户情况、推荐方案、选择原因、接下来产物。
2. 检查 `clarification.status=user_confirmed`；未确认时交回产品经理澄清，用户坚持跳过则记录风险。
3. 采用两步式流程：先生成 PRD 草稿和 `待用户回答问题`，用户回答后再完善最终稿。
4. 草稿阶段不触发审核；最终稿完成后清空阻塞问题，并自动触发 `quality_reviewer` 审核 analyze。
5. 做四轮引导：角色与场景、功能模块、优先级与边界、规则与验收。
6. 每个功能必须有 `M{模块号}-F{功能号}`。
7. 每个功能必须标记 P0/P1/P2。
8. P0 功能必须有业务规则、字段/状态/权限、异常和验收标准。
9. 明确不做清单，防止范围失控。

## 检查表

- 是否有目标用户和核心场景。
- 是否有功能编号体系。
- 是否有 P0/P1/P2。
- 是否有不做清单。
- 是否每个 P0 都能交给架构师继续设计。
- 是否没有未回答的阻塞问题。
- 是否只有 final 状态才触发 analyze 审核。
