# 信息架构参考

信息架构用于在视觉表现前确定结构：用户从哪里来、先看什么、做什么、做完去哪。

## 必须先查

- PRD 中的 P0 功能编号和高频流程。
- 技术架构中的路由、导航、权限、数据对象和模块边界。
- 现有页面、布局、导航和 URL 约定。

## 设计动作

- 按使用频率排序页面和入口，不按组织架构堆菜单。
- 每个页面只定义一个核心任务；辅助模块必须服务这个任务。
- 明确页面层级、入口来源、上下文对象、下一步和退出路径。
- 合并重复入口、重复详情、重复表单和低频模块。
- 记录本页不做什么，避免配置、审计、报表、审核等能力错放。

## 输出要求

- 页面地图和 URL/文件路径策略。
- 关键用户流，包含分支和异常去向。
- 页面任务卡和模块准入表。
- 需求到界面的追溯关系：`Mx-Fx -> 页面 -> 控件/模块 -> 状态 -> 原型路径`。
